# 0.8.0 — verified publish history (unreleased)

Publishing now hashes the verified stored body for its baseline. Schema-2 snapshots
track compiled input, submitted markup and stored markup separately, preventing server
rewriting from appearing as retained remote edits. Unchanged history skips writes,
including forced publishes, without an extra verification fetch.

Local edits can be merged after server rewriting when remote storage is unchanged.
Actual retained remote contributions remain protected from ordinary publishing.
Concurrent edits to the same storage block can still conflict conservatively.

Old ambiguous snapshots require review and a forced publish to establish new history.
Source files, CDATA and raw storage are never normalized for authorization or migration.
Display normalization is unchanged. Failed readback or a changed verification version
does not advance history; preview remains read-only.

Validation uses simulated server rewrites and the full Gradle build. Live Confluence
verification and recorded REST fixtures are not part of this change.

Full Gradle build: 348 tests passed, no failures or skips.

Build documentation versions stay in sync automatically.

`build` now runs `updateReadmeVersion` (ported from jira-mark), which rewrites the plugin version inside `<!-- wiki-mark-version:start -->` marked README blocks from the plugin version in the root `build.gradle`. Run `.\gradlew.bat updateReadmeVersion` to update documentation without running the full build; the task writes only on change and fails on missing or unbalanced markers. README install examples now show 0.8.0, and the CLI jar references in the command cheat sheet and import reference match the build.
