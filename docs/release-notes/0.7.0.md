# 0.7.0 — import baseline refresh (unreleased)

Lossless imports now establish or refresh the local publish baseline when their compiled
storage exactly matches the fetched page and their headers still target that page. Import
followed by a local edit can publish without `--force` if the remote revision is unchanged.
The exactness check runs even without `--verify`.

Previews, lossy imports, retargeted imports, and `--no-baseline` do not refresh state.
Successful qualifying imports invalidate older merge history. Same-version exact local
baseline evidence takes precedence over stale copied hashes in remote version messages.

Publishing remains strict about changed remote versions and raw storage. Conflict messages
include remote and baseline versions, editor/time when available, a diff, and overwrite or
re-import guidance. Equality still skips writes and HTTP 409 still fails.

Baselines belong to each checkout under `.gradle/confluence-publish/baselines`. Resetting
legacy publish state preserves them; deleting `.gradle` removes them. Import manifests
continue to record provenance and are not used as publish baselines.

Validation: full Gradle build passed with 342 tests (262 core, 20 CLI, 35 Gradle unit,
25 packaged functional), zero failures or skips. Regression coverage includes stale tags,
stale merge history, failed imports preserving history, and revision-only remote drift.
Live-server normalization was not measured; drift uses exact raw storage hashes.
